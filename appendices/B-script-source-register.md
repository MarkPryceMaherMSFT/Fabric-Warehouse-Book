**Script-source baseline: 8 October 2026; structural revision: 9 October; targeted documentation refresh: 9 November 2026.** This is a curated register of source implementations, not a claim that all their code is embedded in the book, supported by Microsoft, or tested against a Fabric tenant. It contains **21 main gists, two supplementary cancellation gists and 23 repository/toolbox entries**, plus three historical refresh examples and two older exclusions. Some selected sources are deliberately negative examples.

The strict machine-readable companion, [script-register.json](../sources/script-register.json), is the reconciliation authority: it records all 51 stable IDs, canonical URLs, full revision-pinned URLs, author and license references, dates, dependencies, product applicability, suggested chapter mappings, final integration states, actual file links, effects, and required corrections. Original G01-G21 and R01-R23 numbering is unchanged. The full revision is more reliable than a moving branch or the date shown on a GitHub landing page. Source filenames are preserved even when misleading.

## How to use this register

The selection window is **8 October 2023 through 8 October 2026, inclusive**, applied to substantive script work. A recent API `updated_at` value does not turn an old implementation into a recent one. The table's **content date** is the last meaningful change identified by the source review; the JSON also records creation and touched metadata where established. A nonzero Git diff is evidence of changed text, not a guarantee of changed behavior. Repository creation/push dates were not substituted for file-level dates; unavailable metadata is explicitly null.

**The existing source integrations are carried into the revised 42-chapter book and 18 standalone scripts, including Chapters 31-36.** The scripts-directory README was also reviewed but is not counted as an executable script. Each entry has a final state: explicitly attributed adaptation/safe replacement, citation/discussion only, retained research/caution not used in a worked example, historical-only, or excluded. The JSON's `actual_files` records observed use separately from `proposed_chapters`, which remains a suggested thematic mapping. An empty actual-file list is a final negative match, not pending work. A generic repository citation does not establish adoption of every file.

The 10 October architecture expansion rebases the current file and chapter associations without changing source pins or adoption counts. The JSON retains the dated 9 October reconciliation and numbering history and adds an `architecture_revision` mapping. New paper summaries and documentation images are recorded in the bibliography and image register, not counted as newly adopted executable code.

The 9 November refresh adds a provisioning-status guard to the existing G08 book adaptation and discusses R09/R10 explicitly as reference-only examples. The adapted-source count stays 19; citation/discussion-only sources become 13 and retained research sources 14. All public-code pins and the original selection window remain unchanged. No additional external implementation is copied.

Effects describe the **original source**:

- **R**: read-only service queries. These can consume capacity and expose query text or identities.
- **M**: writes data, statistics, metadata, configuration, objects, or files.
- **D**: contains destructive/disruptive operations, including DROP, TRUNCATE, or automatic KILL.
- **Mixed**: read-only paths coexist with installation, file writes, optional mutations, or an unreviewed dependency.

Authors are **Mark Pryce-Maher (`MarkPryceMaherMSFT`)** for all G/H/X entries and R14-R23; R01-R13 are attributed to **Microsoft Fabric CAT and repository contributors**, without inventing individual bylines. `A` below means the author has authorized manuscript use but **no explicit public reuse license was found**. It is not MIT. `MIT-T`, `MIT-P`, and `Apache` refer to the exact license snapshots in [Third-party notices](../THIRD_PARTY_NOTICES.md).

## Integration and publication rules

An actual adaptation needs a listing-level attribution and, for a separate script, an attribution header naming the source ID, author, canonical URL, full pinned URL, revision/date, license basis and changes. A reference in this appendix alone is not a sufficient change notice. Do not embed notebook outputs containing identifiers, tokens, SQL text or data from somebody else's environment.

Each exercise must name its execution surface: Warehouse T-SQL, endpoint T-SQL, Spark, external client, or REST. It must distinguish install-time DDL from run-time SELECT and explain cleanup. Use original `book.LabXX...` objects instead of inheriting destructive source names. Inventory and dry-run modes are not universally write-free: local files or Lakehouse audit records can still be created.

The source review was static. API contracts, permission minima, reader compatibility, preview enrollment, dependency licensing and corrected algorithms require isolated validation before production or publication claims. No script here has been represented as tenant-tested. Prefer linked cautionary sources and small original safe exercises over copying large unsafe tools.
