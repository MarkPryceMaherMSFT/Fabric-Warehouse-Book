This follow-up checks the [public Warehouse documentation hub](https://learn.microsoft.com/en-us/fabric/data-warehouse/), its full table of contents, current source changes and selected existing guidance that the manuscript did not explain fully. **A documentation audit is not a claim that every feature has just shipped, every page was reread in full or every tenant can use an announced preview.**

Complete, non-truncated recursive inventories show **all 166 text entries in `docs/data-warehouse/` unchanged: 161 Markdown and five YAML files**. This compares file content hashes, not just page dates. It is not a statement that all Fabric documentation is unchanged: adjacent lifecycle/security guidance has changes, and shared SQL/REST references are maintained separately.

That result explains an important boundary in [Appendix K](K-ignite-2026-availability.md). The 17 November announcement can be newer than its linked implementation guide. An unchanged guide does not cancel the announcement, but a launch paragraph does not supply missing API payloads, permissions or a universal rollout guarantee.

The TOC/citation check also identified **coverage leads**, not automatic errors: a chapter can explain a topic without citing every related how-to. The additions below come from reading the actual selected guides and comparing their contracts with the book.

### A real correction: delayed paginated-report protection guidance

The [10 November correction](https://github.com/MicrosoftDocs/fabric-docs/commit/a8b12242fd92663fca6d3804ca2112b4083929f9) deliberately removed the paginated-report outbound-protection article because deployment was delayed. This is **withdrawn documentation, not a demonstrated runtime feature deprecation**, and it establishes no replacement launch date.

[Chapter 12](../parts/02-building-analytical-solutions/12-security-and-governance.md#a-network-allow-list-is-not-a-data-permission) now separates **report > model** from **model > Warehouse/OneLake source** network checks. Same-workspace report access does not exempt the model's source connection; the exact SQL/OneLake mode controls the documented rule type. A network allow list grants no data permission, replaces no RLS/CLS policy and does not govern every browser/export route.

The [current interactive-report guide](https://learn.microsoft.com/en-us/fabric/security/workspace-outbound-access-protection-power-bi-reports) and [semantic-model guide](https://learn.microsoft.com/en-us/fabric/security/workspace-outbound-access-protection-semantic-models) supply those preview/exclusion boundaries. Do not recover the removed Analysis Services/XMLA recipe from an old link and present it as a supported current paginated-report solution.

## What this review does not change

The **18 November Ignite labels remain explicit**: GA core sync is separate from the Preview existing-endpoint upgrade; GPU/live diagnostics are limited evaluations; Warehouse Clones are Limited Private Preview; cooldown/aliases promised for November and plans/cards described as coming soon are not general-customer setup dependencies.

The **9 November roadmap snapshot**, earlier chapter-wide audit, Build crosswalk, selected script revisions, canonical seed and image/licence bytes remain fixed. The range-band query is original book SQL, evaluated offline against the supplied synthetic rows; it is not a Fabric tenant measurement. No preview enrollment, ownership change, source write, diagnostic upload, live configuration or deployment is performed.
